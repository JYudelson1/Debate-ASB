01 / EXPOSURE BREADTH

Does seeing more code predict capture?

Each point is one retained codebase × epoch × variant. The percentage uses distinct returned source/configuration lines divided by that codebase’s saved reference inventory. File listings do not count as reading.

X: selected code-coverage measure (%). Y: mechanism capture (0 or 1); vertical jitter separates overlapping points. Click a point for its evidence.

Quartile bins use observed coverage in the current selection; ties stay together. Labels show catches / sample epochs; these are descriptive rates.

Why pooling can mislead, and what “within” means

Small codebases can be easier both to cover and to catch. “Within codebase” subtracts each codebase’s mean coverage and mean outcome before calculating Pearson r. “Within codebase × variant” does this separately for each protocol/codebase cell, using its observed epochs. Constant-outcome groups contribute no outcome variation. These are correlations of residuals, not causal effect estimates.

The saved denominator is the local reference snapshot at collection time. We verify returned text against it, but cannot prove that every unread historical file was identical. Partial long lines receive one line of presentation credit; use “Only reference-verified lines” for a sensitivity check. This is not a claim about understanding.

Does rereading the sabotage help?

A target-region read returns ≥1 numbered line from a reviewed implementation region. A region hit is a location-based exposure proxy; it does not establish that the whole mechanism was visible or understood.

04 / EVIDENCE ALLOCATION

What competes with the sabotage?

Use retained bundles to measure content selection, and returned line presentations to measure browsing. Catalog signatures can occur incidentally in a bundle about a different concern; signature overlap does not prove that the catalog issue was its focus. Neither is a token-spend or neural-attention measurement. “Other” includes ordinary code, uncatalogued concerns, docs and data; it is not a count of new bugs.

Repeated catalog issues

Verified code-signature matches only; counts are bundles, not distinct defects. Click an issue for its original annotation and matching bundles.

Browsing allocation

Returned line presentations, including repeats. Target-region lines take precedence over known-signature lines, then PAPER.md, then other. Known-signature line counts are a conservative lower bound, not the full region occupied by a known issue. Pooled line shares weight longer reads more heavily; most of the codebase is non-target by construction, so a large other share alone does not establish wasted effort. Execution and unreturned search traversals have no source-line attribution.

Catalog matching limits

“Known, verified signature” uses the saved code_match annotation. “Possible catalog match” includes quote-fidelity failures and location hints; these are not confirmed known-issue selections. We preserve all original categories: bug, quirk, mismatch and misleading. Target overlap and catalog matches can coexist; the mutually exclusive allocation chart gives target capture priority. An absent match does not establish novelty.

06 / AUDIT & REPRODUCTION

What changed, and how to reproduce it

Scoring corrections

Source-bound overrides are separate from the original ledgers. Existing per-bundle bug, candidate and paper judgments remain unchanged. New capture judgments do not receive invented single-bundle completeness labels.

Denominators & boundaries

  • Primary unit: log × sample ID × epoch, once only. The selected reports’ baselines and unrequested budget variants are excluded.
  • Eligible capture denominator: parsed sabotaged sample epochs with resolved yes/partial/no judgments. Partial counts as zero. Completed zero-candidate outputs remain misses.
  • Correlations use eligible rows with complete retained extraction traces and available measurements. No p-values or claims of independent replicates.
  • Variant comparisons differ in prompts, bundle counts, inspection budgets and retry policies. Epoch numbers do not establish matched seeds.
  • Content credited from source reads is what was returned, not every file searched or listed. No binary decoding or hidden reasoning reconstruction.

Inputs and provenance

This is a standalone offline report. Original observations, excerpts, catalog annotations and tool responses are embedded. Input hashes, source revisions, model/provider metadata, logged costs and missing seeds are retained.
